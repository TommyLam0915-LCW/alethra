## 1. 研究首頁指標論證

### 問題
研究首頁顯示「勝率 62.5%」與「收益 +18.3%」，但這些數字如何計算？資料來源？時間範圍？

### 計算定義

**勝率 (Win Rate)**
- **計算範圍**：僅計算狀態為「已鎖定」且已完成回測的實驗
- **計算方式**：`勝率 = (獲利交易次數 / 總交易次數) × 100%`
- **資料來源**：每個實驗的回測引擎結果（`backtest_results.trades`）
- **加權方式**：所有已鎖定實驗的簡單平均（不考慮資金分配）
- **時間範圍**：回測區間內的所有交易（由實驗定義）
- **範例**：4 個已鎖定實驗，勝率分別為 68.2%、55.0%、60.0%、66.7% → 平均 62.5%

**模擬累計收益 (Simulated Return)**
- **計算範圍**：僅計算狀態為「已鎖定」且已完成回測的實驗
- **計算方式**：`收益 = (回測期末淨值 - 回測期初淨值) / 回測期初淨值 × 100%`
- **資料來源**：回測引擎的權益曲線（`backtest_results.equity_curve`）
- **加權方式**：所有已鎖定實驗的簡單平均
- **時間範圍**：回測區間（由實驗定義）
- **重要限制**：這是**模擬回測結果**，非真實交易收益，不代表未來表現

### 顯示建議

**方向 B（推薦）的處理方式**：
1. **明確標示**：指標卡片顯示「整體勝率 ?」與「模擬累計收益 ?」，問號圖示懸浮顯示計算說明
2. **提供脈絡**：指標下方顯示「基於 4 個已鎖定實驗的模擬回測」
3. **區分狀態**：草稿/探索中的實驗不納入計算，但顯示「—」而非隱藏
4. **可選隱藏**：設定中可關閉指標顯示（避免誤解）

**替代方案**：
- 不顯示聚合指標，僅顯示實驗數量與狀態分佈
- 顯示「已完成回測」數量而非勝率/收益（避免誤導）

### 決策點
**Owner 需決定**：是否顯示勝率/收益指標？若顯示，是否接受上述計算定義與標示方式？

## 2. 響應式規格

### 問題
固定 15%/55%/30% 比例在不同螢幕尺寸下可能不適用。需要定義：
- 最小/最大寬度
- 短螢幕（高度 < 800px）行為
- 平板（768px - 1024px）行為
- 手機（< 768px）行為

### 方向 B 響應式規格

**Desktop（≥ 1280px）**
- 三欄佈局：左側 200px（固定）/ 中央 flex / 右側 300px（固定）
- 最小高度：720px
- 圖表區域：最小 400px 高度
- 研究面板：可折疊（點擊按鈕隱藏，中央區域擴展）

**Compact Desktop（1024px - 1279px）**
- 三欄佈局：左側 180px / 中央 flex / 右側 280px
- 研究面板預設折疊
- 工具列圖示化（時間框架改為圖示選擇器）

**Tablet（768px - 1023px）**
- **兩欄佈局**：左側觀察名單隱藏（抽屜式）/ 中央圖表 + 底部研究面板
- 底部研究面板高度：240px（可拖曳調整）
- 導航：頂部 App Bar 保留，但隱藏部分項目（「紀錄」移至設定選單）

**Mobile（< 768px）**
- **單欄佈局**：觀察名單、圖表、研究面板分頁切換
- 底部導航：4 個項目（策略 / 工作台 / 持倉 / 設定）
- 圖表區域：高度 200px（固定）
- 研究面板：卡片式列表（非側邊欄）

**Short Height（高度 < 800px）**
- 回放控制列：壓縮為單行（隱藏速度控制）
- 工具列：隱藏指標按鈕（僅顯示時間框架）
- 研究面板：隱藏證據卡片（僅顯示策略規格）

### 斷點定義
```css
/* Mobile first */
@media (min-width: 768px) { /* Tablet */ }
@media (min-width: 1024px) { /* Compact Desktop */ }
@media (min-width: 1280px) { /* Desktop */ }
@media (max-height: 800px) { /* Short Height */ }
```

### 方向 A 與 C 的差異
- **方向 A（Trading Platform）**：Desktop 固定比例，Tablet 切換為兩欄，Mobile 不支援（僅 Desktop）
- **方向 C（Minimalist）**：所有尺寸皆為單欄，Desktop 使用 max-width: 720px 居中

## 3. 核心術語審查（15-20 個高頻詞）

### 問題
原提案提供 85 個術語，但 Owner 只需審查最關鍵的 15-20 個。

### 核心術語表（18 個）

| # | 中文 | 英文 | 使用場景 | 避免混用 |
|---|------|------|---------|---------|
| 1 | **實驗** | Experiment | 研究單位（包含假設、方法、結果） | 策略、版本、Run |
| 2 | **策略** | Strategy | 實驗內的交易方法（如「均線突破」） | 實驗、模型 |
| 3 | **回測** | Backtest | 歷史資料測試 | 模擬、回放 |
| 4 | **模擬交易** | Paper Trading / Simulation | 虛擬資金交易 | 真實交易、回放 |
| 5 | **回放** | Replay | 歷史資料逐步播放 | 回測、模擬 |
| 6 | **持倉** | Position | 目前持有的標的 | 倉位、部位、投資 |
| 7 | **訂單** | Order | 買入/賣出指令 | 交易、委託 |
| 8 | **成交** | Fill / Trade | 訂單執行結果 | 交易、訂單 |
| 9 | **勝率** | Win Rate | 獲利交易比例 | 成功率、準確率 |
| 10 | **收益** | Return | 投資報酬 | 獲利、報酬率 |
| 11 | **盈虧** | P&L (Profit and Loss) | 未實現/已實現損益 | 利潤、虧損 |
| 12 | **觀察名單** | Watchlist | 追蹤的標的列表 | 自選股、關注列表 |
| 13 | **工作台** | Workspace | 主要交易介面 | 交易面板、儀表板 |
| 14 | **研究面板** | Research Panel | 工作台右側資訊區 | 資訊面板、詳情 |
| 15 | **證據** | Evidence | 支持決策的數據/分析 | 資料、結果 |
| 16 | **已鎖定** | Locked | 實驗完成且不可修改 | 完成、封存 |
| 17 | **探索中** | Exploring | 實驗進行中 | 測試、執行中 |
| 18 | **草稿** | Draft | 實驗初始狀態 | 新建、未開始 |

### 術語原則
1. **一致性**：同一概念全域使用相同術語（如「持倉」不混用「倉位」「部位」）
2. **具體性**：使用具體動作詞（如「買入 100 股」而非「確認」）
3. **區分性**：區分相似概念（如「回測」vs「模擬交易」vs「回放」）
4. **繁體中文**：所有 UI 文字使用繁體中文（香港慣用語）

### 決策點
**Owner 需決定**：是否接受此 18 個核心術語？是否有需要調整的項目？

## 4. 實作計劃（無預設時程）

### 問題
原提案预设 7 週時程，但 Owner 要求根據實際工作量與依賴關係重新規劃。

### Phase 定義

**Phase 1：Visual Language & Design Tokens**
- **交付物**：
  - Design tokens（顏色、字體、間距、圓角、陰影）
  - CSS variables 定義
  - 基礎組件樣式（按鈕、輸入框、卡片）
- **範圍**：僅 CSS/樣式，不改動組件結構
- **依賴**：無
- **驗收**：所有頁面使用新 tokens，視覺一致性檢查通過
- **工作量估計**：3-5 天

**Phase 2：Login Page Redesign**
- **交付物**：
  - 登入頁重新設計（方向 B 規格）
  - 響應式支援（Desktop/Mobile）
  - 文案更新（使用核心術語表）
- **範圍**：`/login` 頁面
- **依賴**：Phase 1（design tokens）
- **驗收**：Desktop/Mobile 視覺檢查、表單功能正常、文案正確
- **工作量估計**：2-3 天

**Phase 3：Research Page Redesign**
- **交付物**：
  - 研究首頁重新設計（方向 B 規格）
  - 指標卡片（勝率/收益，含說明）
  - 實驗列表（卡片式，含狀態標籤）
  - 響應式支援
- **範圍**：`/dashboard` 頁面
- **依賴**：Phase 1（design tokens）、Phase 2（AppShell 更新）
- **驗收**：指標計算正確、列表篩選功能正常、響應式檢查
- **工作量估計**：3-4 天

**Phase 4：Workspace Redesign**
- **交付物**：
  - 工作台重新設計（方向 B 三欄佈局）
  - Context bar（實驗/模式/回放狀態）
  - 研究面板（策略規格/證據/回放設定）
  - 響應式支援（Desktop/Tablet/Mobile）
- **範圍**：`/workspace` 頁面
- **依賴**：Phase 1-3（design tokens、AppShell、研究頁面組件）
- **驗收**：三欄佈局功能正常、研究面板資訊正確、響應式檢查、快捷鍵（⌘K）
- **工作量估計**：5-7 天

**Phase 5：Portfolio & Journal Redesign**
- **交付物**：
  - 投資組合頁面重新設計
  - 紀錄頁面重新設計
  - 響應式支援
- **範圍**：`/paper-portfolio`、`/paper-portfolio?view=journal`
- **依賴**：Phase 1-4（design tokens、AppShell、組件）
- **驗收**：持倉列表功能正常、紀錄顯示正確、響應式檢查
- **工作量估計**：3-4 天

### 時程估算

**最樂觀**：16 天（3+2+3+5+3）  
**最保守**：23 天（5+3+4+7+4）  
**建議**：18-20 天（不含週末）

**關鍵路徑**：Phase 1 → Phase 2 → Phase 3 → Phase 4 → Phase 5  
（每個 Phase 依賴前一個 Phase 的交付物）

### 風險與緩解

**風險 1：響應式測試不足**
- **緩解**：每個 Phase 結束時進行 Desktop/Tablet/Mobile 視覺檢查
- **工具**：Chrome DevTools 裝置模擬 + 實際裝置測試

**風險 2：術語不一致**
- **緩解**：Phase 2 開始前，全域搜尋替換舊術語
- **工具**：`grep` 搜尋 + 人工審查

**風險 3：指標計算錯誤**
- **緩解**：Phase 3 實作指標計算邏輯時，撰寫單元測試
- **測試**：驗證勝率/收益計算與回測引擎結果一致

### 決策點
**Owner 需決定**：
1. 是否接受此 5 個 Phase 的劃分？
2. 是否同意 18-20 天的工作量估計？
3. 是否優先實作 Phase 1-3（Visual + Login + Research），Phase 4-5 延後？

## 5. 決策項目精簡（3-5 個）

### 原提案：8 個決策項目
1. 設計方向確認
2. 研究首頁必要性
3. 研究面板內容
4. Mobile Bottom Tab Bar 項目
5. 可選功能優先級
6. 文案系統採用
7. 實作時程
8. 測試策略

### 精簡後：4 個核心決策

**決策 1：設計方向選擇**
- **選項**：
  - A. Trading Platform Standard（深色、密集、專業）
  - B. Research-First Professional Workspace（淺色、卡片、研究導向）⭐ 推薦
  - C. Minimalist Research Tool（極簡、散文式、閱讀優先）
- **影響**：整體視覺風格與資訊架構
- **建議**：方向 B（符合 Alethra 定位、實作成本可控、與競品接軌）
- **參考**：視覺原型 `docs/design-prototypes/direction-b-research-first.html`

**決策 2：研究首頁指標顯示**
- **選項**：
  - A. 顯示勝率/收益指標（含說明與問號圖示）
  - B. 僅顯示實驗數量與狀態分佈（不顯示聚合指標）
  - C. 不顯示指標卡片，僅顯示實驗列表
- **影響**：用戶對研究進展的理解
- **建議**：選項 A（提供脈絡，但明確標示為模擬結果）
- **參考**：本文件 §1「研究首頁指標論證」

**決策 3：核心術語採用**
- **選項**：
  - A. 全盤採用 18 個核心術語（本文件 §3）
  - B. 部分採用（Owner 指定調整項目）
  - C. 暫不採用，維持現狀
- **影響**：產品術語一致性與專業感
- **建議**：選項 A（一致性是專業產品的基礎）
- **參考**：本文件 §3「核心術語審查」

**決策 4：實作優先級**
- **選項**：
  - A. 完整實作 Phase 1-5（18-20 天）
  - B. 優先實作 Phase 1-3（Visual + Login + Research，8-12 天），Phase 4-5 延後
  - C. 僅實作 Phase 1-2（Visual + Login，5-8 天），其餘延後
- **影響**：專案時程與資源分配
- **建議**：選項 B（先完成核心頁面，工作台延後）
- **參考**：本文件 §4「實作計劃」
