# 主持人指南

**狀態：未執行（NOT RUN）。** 本指南是給未來主持人的材料；到目前為止沒有任何真實受試者，沒有結果、沒有成功率、沒有滿意度。

## 目的

觀察一位有投資研究習慣、但沒有參與這個產品開發的人，能否在不接受逐步指示的情況下，自己判斷目前的狀態、找到下一步，並完成研究相關工作。我們要知道的是**產品是否說得清楚、入口是否真的可用**，不是受試者是否聰明。

## 誰符合資格

- 有做投資研究或記錄習慣（例如自己記筆記、比較策略、看回測）。
- 不需要懂程式、資料庫、artifact、checksum、macro F1、UUID。
- 未參與本產品開發、未看過本測試包、未聽過任務內容。
- 自願參與，可隨時停止。

不符合以上條件的人（包括開發者、實習生、看過本文件的人）只能做工程走查，不能算作受試者。

## 角色

- **主持人**：讀任務、給提示、控制節奏。不要操作滑鼠鍵盤，除非受試者明確要求協助。
- **記錄員**（可與主持人同一人，但同一時間只做一件事）：填 `result-recording-sheet.md`，逐字記下原話。
- **工程師**：只在系統故障時處理環境，不回答產品問題、不引導操作。

## 開始前檢查（5 分鐘）

1. 依 `environment-and-accounts.md` 確認前端、後端、worker 都在線，並記下 `worker-heartbeat.json` 的 `beat_at`。
2. 確認使用的是**候選環境與 disposable 資料庫**，不是共享 8099。
3. 向受試者說明：資料全部是合成示範資料、不是投資建議、沒有真實金錢；可以隨時停止。
4. 取得記錄同意（文字筆記、是否可錄音）。未同意就不錄。
5. 只把該受試者任務所需的登入資料交給對方；不要展示憑證檔內容。

## 流程（約 30–45 分鐘）

1. **開場 3 分鐘**：目的、合成資料聲明、無正確答案、可隨時停止。
2. **出聲思考練習 2 分鐘**：請對方在看第一個畫面時，說出「我看到什麼、我以為下一步會怎樣」。
3. **任務 A–E**：依下方「任務與帳號對應」次序執行。每項開始前只讀任務目的（見 `participant-task-sheet.md`），不講按哪裡。
4. **每項之間不要總結對錯**，只說「好，我們下一項」。
5. **收尾 3 分鐘**：問「哪一部分最令你猶豫？」「有沒有哪個字或數字你仍然不明白？」記錄原話。

## 任務與帳號對應

| 任務 | 帳號 | 該帳號目前的真實狀態（主持人知道、但不提示） |
| --- | --- | --- |
| A 找回一次研究，說明假設及結果 | 已訓練帳號 | 1 個已鎖定策略版本、1 次回測結果、205 筆已確認決策 |
| B 修改一個策略，保留原版並比較差異 | 資料不足帳號 | 1 個已鎖定版本（5 筆決策、3 筆已確認）；可修訂並保留原版 |
| C 判斷目前為何能或不能訓練，指出下一步 | 三個帳號各做一次（空白 → 資料不足 → 已訓練） | 空白：無實驗、無同意；資料不足：無同意、決策不足；已訓練：有同意、2 個模型版本，但較嚴格品質門檻未達 |
| D 比較兩個模型，說明差異及證據限制 | 已訓練帳號 | 2 個模型版本，來自同一份 205 筆合成快照（checksum `8f21bbbe…`） |

若受試者先做 C 的空白帳號，之後才做 B，請在 B 之前重新登入資料不足帳號；不要讓對方在錯誤帳號裡猜。

## 提示階梯（只在受試者停住 ≥ 20 秒或主動求助時使用）

按順序使用，每次只升一級，並在記錄表填上層級。

- **L0 無提示**：不提問、不指方向，只等待。
- **L1 重述目的**：把任務目的原句再說一次，不加操作詞。
- **L2 指向區域**：只說「你可以看看畫面上方／下方那一區」，不講控制項名稱。
- **L3 指出控制項**：說出該按鈕或欄位在畫面上的文字（例如「有一個『記錄同意』的按鈕」），但不代為操作。
- **L4 代為操作**：主持人實際操作。**一旦 L4，該任務標記為「非獨立完成」**，即使最後結果正確。

不可做的事：說出正確答案、說「你應該先⋯⋯」、把 UUID 或資料庫指令給受試者、替對方解讀數字、在對方做錯時說「其實是⋯⋯」。

## 什麼算完成

- **獨立完成**：L0 或僅 L1 之下完成任務目的。
- **提示後完成**：使用 L2–L3 後完成；記錄層級，**不得寫成獨立完成**。
- **未完成／放棄**：L4、超過 10 分鐘無進展、或受試者主動放棄；記錄原因與原話。

## 記錄規則（每一項任務）

1. 先記錄**無提示**下的行為與時間，再記錄提示後發生什麼。
2. 時間由主持人讀完任務目的開始，到受試者表示完成或放棄為止。
3. 「返回／誤點」計次：任何回到上一頁、重複點擊、或明顯點錯後自行修正。
4. 錯誤或放棄：寫下發生在哪一步、畫面顯示什麼、受試者說了什麼。
5. 對資料及結果的誤解：逐字記錄，不要替對方修正認知；例如把合成資料當真實市場、把模型分數當回報預測。
6. 是否阻礙主要工作：這一項失敗是否讓對方無法完成原本想做的研究。
7. **空白比猜測好**：不確定就留空並在備註寫「未觀察」。

## 預期的工程事實（只用來判斷誤解，不可提示）

- 空白帳號：沒有任何實驗；首頁與訓練頁都提供「建立第一個實驗／策略」的入口；資格徽章顯示「不符合（見下方原因）」，原因是尚未記錄決策與同意。
- 資料不足帳號：有 5 筆決策（3 筆已確認）；同意未勾選，按鈕在未勾選前不可用；資格徽章顯示「不符合（見下方原因）」。
- 已訓練帳號：205 筆已確認決策、1 個有效同意、2 個模型版本；資格徽章顯示「未達較嚴格品質門檻」，**不代表訓練被拒絕**——訓練已完成，下一步是執行推論。
- D 的兩個模型版本來自**同一份**快照（checksum `8f21bbbe…`，205 筆合成資料，1 個回放工作階段、41 個決策時點）；版本差異不代表獨立驗證，也不代表回報能力。
- B 的完整流程（建立 → 回測 → 修訂 → 回測 → 比較 → 重新載入）已在候選環境以 tracked Playwright 規格驗證 6/6；但那是工程驗證，不是真人可用性。
- E：重新登入後，先前建立的版本、執行結果與未完成的同意狀態仍在；系統不會自動清除。

## 資料處理與安全

- 只記錄受試者同意的內容；不錄影、不截圖個人資料，除非另有書面同意。
- 不要在對話或檔案中寫入任何密碼、token 或 API key；登入資料只由主持人當面提供。
- 不要把本機 localhost 環境公開到互聯網、不要外傳研究資料、不要付費招募、不要自行寄出邀請；需要對外行動時先取得 owner 批准。
- 不觸碰共享 8099 執行環境的 schema 或權益；只使用候選 disposable 資料庫。

## 每場結束後（復原）

1. 若受試者在資料不足帳號按了「記錄同意」，到訓練頁按「撤銷同意」，確認同意狀態消失。
2. 若受試者在 B 建立了修訂版本，**保留**它；原版仍在，這是任務目的，不要刪除或重置。
3. 不要重設資料庫、不要執行任何清除資料的產品操作；種子腳本只會補缺失的示範資料，不會清空進度。
4. 確認 worker 心跳仍在更新；若不在線，依 `environment-and-accounts.md` 重新啟動並確認回到可用狀態。
5. 登出所有帳號，把記錄表存回本目錄（或 owner 指定位置）。

## 收結寫法

- 每一項任務分開寫「獨立完成／提示後完成／未完成」，並列出提示層級。
- 可以寫觀察到的模式，但**不得**在受試者人數不足時寫「成功率」「滿意度」「大部分使用者」。
- 未實際執行的場次一律標記 **NOT RUN**，不得以工程走查代替。
