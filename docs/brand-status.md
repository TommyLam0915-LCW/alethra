## Brand Guidelines

### Approved Usage

✅ **Do**:
- Use "Alethra" as the product name in all user-facing materials
- Use the tagline "Ideas, tested. Decisions, yours." in marketing
- Reference the brand in documentation and UI
- Use the brand configuration files (brand.yaml, brand.ts) for all text

❌ **Don't**:
- Claim "Alethra" is a registered trademark
- State the brand is approved for unlimited commercial use
- Use phrases like "master the truth" or "winning strategy"
- Claim to predict markets or guarantee profits
- Describe historical tests as proof of future returns
- Imply official relationship with any literary works, movies, or rights holders
- Use logos, props, or official visual materials from related works

### Brand Restrictions

The name "Alethra" may be associated with fictional works. Until legal verification is complete:

1. **No Official Association**: Do not imply any connection to fictional works or their rights holders
2. **No Visual Elements**: Do not use logos, symbols, or visual elements from related works
3. **Clear Origin**: Make clear this is an independent research tool
4. **Legal Review**: Conduct trademark and IP review before commercial launch

## Configuration Files

All brand text should be referenced from configuration files, not hardcoded:

- **brand.yaml**: Master brand configuration (root directory)
- **frontend/src/lib/brand.ts**: TypeScript brand configuration for frontend

### Why Configuration Files?

1. **Centralized Management**: All brand text in one place
2. **Easy Updates**: Change brand text without modifying multiple files
3. **Localization**: Support multiple languages from single source
4. **Consistency**: Ensure brand consistency across all touchpoints
5. **Legal Compliance**: Easy to update disclaimers and restrictions
